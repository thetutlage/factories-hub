Factory state machine

How work moves through the factory: one way in through intake, then two separate queues. Change tasks change the product. Explorations answer a question and keep their artifacts.

1. The way in: intake

Every piece of work starts at intake. A pure positioning or non-goal update with no work is the one exception: you edit context/ directly.

  • A done exploration only produces change tasks. intake E-n reads its findings, context changes and artifacts, then asks only about the gaps left.
  • Conflicts with positioning or a non-goal give three choices: drop the input, make a one-time exception (recorded in ## Questions), or change the line (recorded in ## Context changes).
  • A duplicate (an open task or exploration for the same work) stops intake and names the existing id.

2. Change task queue tasks/T-n

Changes the product on a branch in each repository. The only path that writes to context/.

in progress waiting on you finished the only edge that writes context/
  • review → done is the only place context/ changes. Every item under ## Context changes is shown to you; you accept, change or drop each one.
  • Probe runs on draft, probing and blocked. It finds each thing the task leaves unsettled. It reads the code and the docs for what they settle, asks you the rest in one group with a recommended answer for each, and sets ready when nothing is unsettled.
  • Build picks the lowest-numbered ready task whose depends_on tasks are all done. It commits and pushes task/<id>, opens a pull request, and never merges. A later build reads the open review comments on that pull request.
  • Open: how a task blocked by failed checks gets unblocked. There is no question to answer. Decided to wait for real cases.
  • Open: a run that crashes leaves the task in building with no way out except a manual fix.
  • Finished tasks stay in tasks/ with status done, so depends_on, decision sources and milestone counts keep working.

3. Exploration queue explorations/E-n/

Builds something throwaway to answer one question. Never touches the repositories. Its artifacts are progress and are never deleted.

  • Accept on an exploration changes only its status and findings. Nothing goes to context/, nothing is deleted.
  • Its ## Context changes are a holding place. Intake copies them into the change tasks it makes; they reach context/ only when that change is accepted.
  • The change tasks link back with exploration: E-n. Probe and build read the findings and artifacts at every stage; build uses the artifacts as a reference.
  • No probe, no blocked. Build makes its own decisions in an exploration and writes them in the evidence. No checks run.
  • Discarded explorations stay with their reason and artifacts.
